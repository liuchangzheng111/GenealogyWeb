# GenealogyApp 开发协作说明

本文档帮助新成员快速理解仓库布局、认证流与扩展约定。实现细节以源码中的注释与 XML 文档为准。

## 1. 仓库目录（业务源码）

| 路径 | 职责 |
|------|------|
| `Program.cs` | 依赖注入、中间件、管道终端（含 `/logout`、Blazor Hub、迁移与种子）。 |
| `Controllers/` | REST API：认证匿名，族谱/成员/Dashboard 需登录并做族谱级授权。 |
| `Data/` | `ApplicationDbContext`、设计时工厂、启动种子数据。 |
| `Models/` | EF 实体，与 MySQL 表一一对应（见 `Migrations/`）。 |
| `Services/` | 可注入业务服务：密码哈希、族谱访问判定、Cookie 转发、Blazor 认证状态。 |
| `Pages/`、`Shared/`、`App.razor` | Blazor Server UI 与布局。 |
| `wwwroot/js/` | 登录/注册页使用的 `fetch`（`credentials: 'include'` 携带 Cookie）。 |
| `Migrations/` | **由 `dotnet ef` 生成，勿手改**；改模型后新增迁移。 |

## 2. 认证与授权（必读）

1. **浏览器 → API**：Cookie 名 `GenealogyAuth`，登录由 `POST /api/auth/login` 写入。  
2. **Blazor 服务端 → 同源 API**：默认 `HttpClient` 不会带浏览器 Cookie，故使用 **`CookieForwardingHandler`** + 命名客户端 `GenealogyApi`。  
3. **Blazor `AuthorizeView`**：依赖 **`CookiePrincipalAuthenticationStateProvider`**，从 `HttpContext.User` 读取与 Cookie 一致的 `ClaimsPrincipal`。  
4. **退出登录**：须由**浏览器导航**到 `GET /logout`（见 `Program.cs`），以便 `Set-Cookie` 清除会话；仅靠服务端 `HttpClient` 调 `SignOut` 无法更新浏览器 Cookie。  
5. **族谱数据隔离**：`IGenealogyAccessService` 定义「创建者 **或** `GenealogyUsers` 成员」可见；所有族谱/成员/树接口在控制器内校验。

## 3. 数据库与迁移

- 连接串：`appsettings.json` → `ConnectionStrings:DefaultConnection`。  
- 启动时执行 `Migrate()`，随后 `SeedData.EnsureSeeded`（演示账号见 `SeedData` 常量）。  
- 新增/修改实体：在仓库根执行 `dotnet tool restore` 后 `dotnet dotnet-ef migrations add ...`。

## 4. 协作约定建议

- **API 契约变更**时同步更新根目录 `README.md` 的接口小节。  
- **DTO / 路由**变更时检查 Blazor 页面与 `wwwroot/js/auth.js` 是否仍一致。  
- 提交前 `dotnet build`；若涉及迁移，说明是否需删库或 `database update`。

## 5. 后续扩展挂点（阶段 B 及以后）

- 邀请协作：向 `GenealogyUsers` 写入记录并校验 `Role`。  
- 成员改删：`PersonsController` 与 UI。  
- 祖先树 / 亲缘路径：在现有 `ParentChildren` 上增加查询或只读 SQL。
